# Brainstorming

Use this skill only when the user explicitly asks for brainstorming or design exploration. Do not trigger it automatically for coding, feature, UI, refactoring, or planning requests.

## Process

1. Understand the goal and constraints from the request and existing context.
2. Ask only the questions needed to resolve meaningful ambiguity, one at a time.
3. Keep questions concrete and go straight to the decision.
4. Offer 2–3 concise approaches with trade-offs when multiple approaches are valid.
5. Recommend the simplest suitable approach.
6. Confirm the direction before implementation when the choice materially matters.

## Rules

- Skip brainstorming for obvious, small, or well-specified tasks.
- Do not require a visual companion, design document, commit, or implementation-plan handoff.
- Do not turn a simple task into a formal workshop.
- Prefer existing code and the smallest solution.
- Stop once the user has enough clarity to proceed.
